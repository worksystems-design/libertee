# Analogical Transfer — Structural Tests

## Scenario 1: Default (Binary) mode

**Command:** `/libertee:analogical-transfer "Wie können wir Wissenstransfer zwischen Teams verbessern?"`

**Required:**
- [ ] Section header `## ✋  Setting the Problem` (or matching localized equivalent) — facilitator opening
- [ ] Section header `## 🧬  Abstract Structure`
- [ ] A `Type:` label (e.g. coordination, attention, distribution, replication, etc.) is named
- [ ] Abstract shape stated in 2-3 sentences using domain-neutral language (no "team", "knowledge", "company" vocabulary)
- [ ] Section header `## 🌍  Cross-Domain Map`
- [ ] At least 3 distinct distant domains, each with: precise domain name, analog problem, mechanism, operating principle
- [ ] Domains are demonstrably distant (NOT e.g. "another company" / "a different team" / "another startup") — at least 2 from biology/physics/history/music/games/military or comparable
- [ ] Each operating principle stated in 1 abstract sentence
- [ ] Section header `## 🔄  Transfer`
- [ ] For each principle: a direct/partial/no verdict, a "where it breaks" assessment, an adapted form (or explicit "drop")
- [ ] At least one principle marked as "where it breaks" — not all are clean transfers
- [ ] Facilitator synthesis sections: `🎯  Principles to Apply`, `⚠️  Where the Analogies Break`, `💡  The Frame Shift`

## Scenario 2: Brief mode

**Command:** `/libertee:analogical-transfer "Wie skalieren wir asynchrone Entscheidungen?" --brief`

**Required:**
- [ ] Same four phase headers (✋, 🧬, 🌍, 🔄)
- [ ] Abstract structure in 1-2 sentences (not 2-3)
- [ ] Cross-domain map has exactly 2 domains (not 3+)
- [ ] Mechanism per domain in 1 sentence
- [ ] Transfer verdicts are one-line each
- [ ] Synthesis: top 2 principles only, 1 sentence each
- [ ] No long preambles

## Scenario 3: Polarity mode

**Command:** `/libertee:analogical-transfer "Wie geben wir Teams mehr Autonomie ohne Kontrollverlust?" --polarity`

**Required:**
- [ ] Phase headers as in Scenario 1 through Step 4
- [ ] Synthesis is reframed: at least one operating principle from the map is recognized as one pole of a polarity in the analog domain
- [ ] The polarity is named with two values in the form `X ↔ Y`
- [ ] Synthesis describes the *balancing mechanism* used in the analog domain, not just the principle
- [ ] Transfer guidance addresses adopting the balance, not the principle alone

## Scenario 4: Join abstract

**Command:** `/libertee:analogical-transfer "Unser Onboarding ist langsam und uneinheitlich" --join abstract`

**Required:**
- [ ] After `## ✋  Setting the Problem`, the facilitator addresses the USER directly with the abstraction brief
- [ ] The brief explicitly mentions stripping vocabulary, naming the structural type, examples like constraint/coordination/attention/throughput
- [ ] No `## 🧬  Abstract Structure` section is auto-generated by an AI agent — that's now waiting on the user
- [ ] Once user input arrives: AI Cross-Domain Analyst runs Map and Transfer passes normally
- [ ] Synthesis runs based on the user's abstraction + the AI's map and transfer

## Notes for the runner

The hardest test in Scenario 1 is the **distant-domain** requirement. If the agent returns "like a sports team", "like an orchestra", "like a startup pivoting" — it's settling for nearby/cliché analogies. Push the prompt to be more specific in the agent file: name a precise domain (lichen symbiosis, Roman legion logistics, jazz comping, bee waggle dance), not a category.

The hardest test in Scenario 3 is whether `--polarity` adds value here vs. just being a forced overlay. If polarity-mode produces "well, autonomy and control are a polarity" without learning anything new from the analog domain, the synthesis hasn't done its job — it should show how the analog domain *manages* the tension specifically.
