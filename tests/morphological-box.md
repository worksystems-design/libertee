# Morphological Box — Structural Tests

## Scenario 1: Default (Binary) mode

**Command:** `/libertee:morphological-box "Wie könnte ein neuartiges Onboarding-Format aussehen?"`

**Required:**
- [ ] Section header `## 📦  Framing the Design Problem` (or matching localized equivalent) — facilitator opening
- [ ] Section header `## 🧱  Dimensions`
- [ ] 3 to 6 named dimensions, each with a precise 1-2 sentence description
- [ ] Each dimension is clearly different in *kind* from the others (not three variants of the same axis)
- [ ] Either a "Dependencies flagged" line naming a known correlation, or an explicit "all dimensions are independent"
- [ ] Section header `## 🎲  Variants`
- [ ] 3 to 5 variants listed per dimension
- [ ] Each variant is concrete (not just a label like "approach A") — short sentence describing the design choice
- [ ] At least one provocative variant per dimension (the one that sounds wrong at first)
- [ ] Section header `## 🔀  Combinations`
- [ ] Exactly 3 combinations: marked as "Most Surprising", "Most Plausible", "Uncomfortable but Viable"
- [ ] Each combination explicitly lists the value picked on every dimension
- [ ] Each combination has a 2-3 sentence "What this design is" description
- [ ] Each combination names the trade-off it accepts
- [ ] No enumeration of all combinations — only 3 surface
- [ ] Facilitator synthesis: `🎯  The Recommendation`, `🪞  What the Other Two Reveal`, `💡  The Hidden Dimension`

## Scenario 2: Brief mode

**Command:** `/libertee:morphological-box "Wie strukturieren wir ein internes Wissensformat?" --brief`

**Required:**
- [ ] Same four phase headers (📦, 🧱, 🎲, 🔀)
- [ ] Exactly 3 dimensions (not 6)
- [ ] Exactly 3 variants per dimension (not 5)
- [ ] Combinations described in 1-2 sentences each (not the longer form)
- [ ] Synthesis: top 1 combination, alternatives noted in one line each
- [ ] No long preambles

## Scenario 3: Polarity mode

**Command:** `/libertee:morphological-box "Wie bauen wir unser Hiring-Verfahren neu?" --polarity`

**Required:**
- [ ] Phase headers as in Scenario 1 through Step 4
- [ ] Synthesis identifies at least one dimension where variants are actually points along a polarity
- [ ] The polarity is named with two values in the form `X ↔ Y`
- [ ] Synthesis describes a *balancing mechanism* rather than just a middle variant
- [ ] At least one design recommendation reframes the dimension as "design the tension management" instead of "pick a variant"

## Scenario 4: Join dimensions

**Command:** `/libertee:morphological-box "Wir brauchen eine neue Form von Strategie-Workshops" --join dimensions`

**Required:**
- [ ] After `## 📦  Framing the Design Problem`, the facilitator addresses the USER directly with the decomposition brief
- [ ] The brief explicitly mentions independence, precision, examples like "who pays / when delivery / level of customization"
- [ ] No `## 🧱  Dimensions` section is auto-generated by an AI agent — that's now waiting on the user
- [ ] Once user input arrives: AI Dimensionalist runs Variants and Combinations passes normally
- [ ] Synthesis runs based on the user's dimensions + the AI's variants and combinations

## Notes for the runner

The hardest test in Scenario 1 is the **independence** of the dimensions. If two dimensions essentially co-vary (e.g. "team size" and "communication formality" — bigger teams almost always default to more formality), the combinatorial space is fake and the combinations will feel forced. If you spot this in the output, re-prompt or note it as feedback to sharpen the agent's "dependency-flagging" discipline.

The hardest test for Scenario 1 / Combination 3 is whether **"uncomfortable but viable"** actually triggers something. If it reads as just another sensible option, the agent is being too polite — push for a combination that genuinely makes the team flinch on first read.

Scenario 4 (Join): if Claude is filling in the user role here (no human in loop), the structural test passes either way; what matters is the brief was issued before the AI took over.
