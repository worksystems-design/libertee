# First Principles — Structural Tests

## Scenario 1: Default (Binary) mode

**Command:** `/libertee:first-principles "Wir brauchen ein wöchentliches Status-Meeting"`

**Required:**
- [ ] Section header `## ✋  Setting the Claim` (or matching localized equivalent) — facilitator opening
- [ ] Section header `## 🤔  Decomposition`
- [ ] At least 3 numbered levels (e.g. `Level 1`, `Level 2`, `Level 3`) within the Decomposition section
- [ ] Each level has both an **Answer** component and a **Hidden assumptions** component
- [ ] A **Terminus** marker at the end of the why-chain (one of: bedrock, convention, contradiction)
- [ ] Section header `## ⚖️  Necessity vs. Convention`
- [ ] Markdown table within that section with columns: `#`, `Assumption`, `Category`, `Rationale`
- [ ] Categories used are drawn from: physical necessity, logical necessity, convention, untested
- [ ] A `Contradictions found` block appears below the table (even if "none")
- [ ] Section header `## 🔨  Reconstruction`
- [ ] At least 2 alternative reconstructions presented
- [ ] A `🪨  What Must Stay` and `🪶  What Can Go` substructure (or equivalent) precedes the alternatives
- [ ] A `💡  The Hidden Move` block names one specific insight

## Scenario 2: Brief mode

**Command:** `/libertee:first-principles "Software muss Tests haben" --brief`

**Required:**
- [ ] Same four section headers as Scenario 1 (✋, 🤔, ⚖️, 🔨)
- [ ] Decomposition has exactly 2 levels (not 3-4)
- [ ] Hidden assumptions in each level are 1-line bullets (not multi-line elaborations)
- [ ] Sort table omits the `Rationale` column (or has single-word entries only)
- [ ] Reconstruction has 2 alternatives (not 3)
- [ ] No long preambles before each section

## Scenario 3: Polarity mode

**Command:** `/libertee:first-principles "Open-Office sind besser für Kollaboration" --polarity`

**Required:**
- [ ] Decomposition and Separate phases produce normal output (same structure as Scenario 1)
- [ ] Reconstruction phase is reframed as **Polarity Identification**, not "What stays / what goes"
- [ ] At least one convention from the Separate phase is reframed as managing a polarity
- [ ] Each polarity is named with two values in the form `X ↔ Y` (e.g. "Autonomy ↔ Alignment")
- [ ] For each polarity: upsides of both poles AND downsides of over-emphasis are mapped
- [ ] Output does NOT simply say "the convention is necessary after all" — it identifies *what* the convention manages

## Scenario 4: Join decompose

**Command:** `/libertee:first-principles "Wir müssen jeden Sprint planen" --join decompose`

**Required:**
- [ ] After `## ✋  Setting the Claim`, the facilitator addresses the USER directly with a brief and a request for the why-chain
- [ ] The brief mentions: "3 levels deep", "name assumptions explicitly", "don't accept your own first answer" (or close paraphrases)
- [ ] No `## 🤔  Decomposition` section is auto-generated by an AI agent — that's now waiting on the user
- [ ] Once user input arrives: AI Decomposer runs only the Separate pass (Step 3), producing the standard `## ⚖️  Necessity vs. Convention` table
- [ ] Facilitator runs the Reconstruction synthesis based on the user's decomposition

## Notes for the runner

When checking Scenario 3 (Polarity): the *ratio* of conventions reframed as polarities matters less than the presence of at least one explicit polarity identification. Some claims have no genuine polarity-management hiding in their conventions; the skill should still produce structured output rather than fail silently.

When checking Scenario 4 (Join): if the user input is given mid-stream by Claude itself (no human in the loop), the Separate pass still produces the standard sort table. The structural test passes either way; only the source of the decomposition input differs.
